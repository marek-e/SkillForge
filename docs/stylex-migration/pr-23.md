## What became StyleX, and what stays Tailwind (removed in PR 32)

These are application components, not primitives: most `className` strings are overrides handed to a
component someone else owns, and none of `Card`, `CardTitle`, `CardContent`, `DialogDescription`,
`SelectTrigger` or `Textarea` takes an `sx` prop — so each stays a `className` bridge in a named
`const` with a comment. `stylex.create` covers exactly the DOM these files render themselves.
| File | Kept | Why |
| ------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SkillCard.tsx` | `cursor-pointer hover:ring-foreground/20 transition-shadow` (`Card`) | the live one. `card.tsx` keeps `ring-1 ring-foreground/10` as a utility and composes its `box-shadow` from `--tw-ring-color`; this class is what _writes_ that variable. A StyleX `boxShadow` would write the property, in a layer `ring-1` outranks |
| `SkillCard.tsx` | `flex items-center gap-2` (`CardTitle`), `space-y-2` (`CardContent`) | a caller override on an element `card.tsx` owns, and a `:where(& > :not(:last-child))` child rule |
| `CreateSkillDialog.tsx` | `space-y-4`, `space-y-2` ×4, `sr-only`, `w-full` | the same child rule over the `Label`/`Input`/`Textarea`/`TagsInput`/`Select` controls the form wraps, plus two overrides on components with no `sx` prop |
| `SkillDetailResourceFiles.tsx` | `space-y-2`, `divide-y`, `font-mono text-xs min-h-48` (`Textarea`) | child rules — `divide-y` draws the separators _between_ the row wrappers — and a caller override whose `text-xs` deliberately keeps losing to `textarea.tsx`'s own `md:text-sm` above 48rem |

## Findings

- **A caller's `hover:ring-*` is a `--tw-*` composition, not a ring.** The caller cannot move first:
  the class it passes only sets `--tw-ring-color` for a chain the _component_ writes. Both halves
  migrate together in PR 32; `state-skillsx-card-grid-hover-*` pins that it still paints.
- **A container's paired `text-*` is safe when the component renders every descendant.** The trap
  needs a descendant with a font size and no line height of its own; every element these four
  containers wrap has a paired `text-*`. The one bare inheritor is `TagsInput`'s `<input>`, whose
  size _is_ the inherited 14px, so the ratio lands on the same 20px — measured in both forms.
- **`space-y-*` and `divide-y` are the shape of `-space-x-2` in PR 18**: a
  `:where(& > :not(:last-child))` rule over elements the component wraps. Six survive here, none with
  a StyleX equivalent that keeps its specificity. **`line-clamp-2`** needs its `overflow: hidden` and
  `display: -webkit-box` to clamp; `WebkitLineClamp`/`WebkitBoxOrient` compile.
- **The tag chip's arbitrary height utility** adds a one-unit spacing step to a five-unit one; as the
  `calc()` of the two lengths `lightningcss` folds it to `1.5rem`, the same 24px. It is deliberately
  **not** quoted in a comment: it names a `--*` theme variable, the built-CSS leak PR 13 recorded.

## Observed pre-existing defects (nothing was fixed)

- **The grid card's `truncate` never clips.** `CardTitle` is `flex items-center gap-2` and the
  `truncate` span is a flex item with the default `min-width: auto`, so it grows to its text: in the
  240px case the title box measures **414px inside a 240px card**, the name overflows and the
  ellipsis never engages. Identical in both forms; `skillsx-card-grid-truncated-*` pins it.
- **The resource editor ignores the caller's `text-xs` above 48rem** (`14px` measured), `textarea.tsx`
  keeping `md:text-sm`; and `TagsInput`'s box puts `onClick` on a plain `<div>` with no key handler.

## Findings for conventions.md

- **A caller's `hover:ring-*` cannot migrate before the component's `ring-1`.** The class only writes
  `--tw-ring-color`; the `box-shadow` reading it belongs to the component, so splitting the pair
  silently kills the hover — a caller _blocked_, not merely shadowed (cf. "A caller's utility also
  shadows…").
- **`VITE_VISUAL_GALLERY` does not gate the CSS.** Gallery-only Tailwind utilities reach the shipped
  stylesheet although the gallery's JS is tree-shaken out, so "Gallery cases are append-only" should
  add that a case may only use utilities the app already emits — or the next row's built-CSS
  comparison reads them as additions.
- **A `transition-colors` element must settle before its computed colour is read**: the selected
  resource row reads `oklab(0 0 0 / 0)` straight after the click and `oklab(0.97 0 0 / 0.5)` 400ms
  later, so a live check needs the settle the specs take.
