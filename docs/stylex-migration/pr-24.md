**Moved to `sx` instead** (`Button` is the only primitive here with one): the sort headers' `-ml-2`, the
filter buttons' `h-8 text-xs`, the delete action's `hover:text-destructive text-muted-foreground
hover:bg-destructive/10 dark:hover:bg-destructive/20`, and the copy button's
`text-muted-foreground hover:text-foreground`.

**Why the palette colours stay classes.** `text-yellow-400` is `color: var(--color-yellow-400)` and the
opacity-modified ones a `color-mix(in oklab, var(--color-yellow-400) N%, transparent)` behind an
`@supports` pair (read off the built CSS). A StyleX rule may not reference a Tailwind-generated
`--color-*`, and the literal `oklch(85.2% 0.199 91.936)` is folded by lightningcss into a hex/`lab()`
pair, so the _computed_ string would change (PR 22 measured that fold); `text-green-500` is the same
shape. And `group-hover/button:fill-yellow-400/50` reaches the star through the literal `group/button`
class, which `button.tsx` keeps **naming this file and `routes/project-detail.tsx`**. **Two `sx` merges
also drop an arm on purpose:** `stylex.props` merges a property whole, so an `sx` replaces `ghost`'s
entire `color`/`backgroundColor` — and its `aria-expanded:text-foreground` was **already shadowed** (a
plain `text-muted-foreground` utility beats any `priorityN` rule), so the `sx` declares no such arm for
`color`, while `aria-expanded:bg-muted` was **not**, so the delete button restates it.

## Findings for conventions.md

- **A comment word need not look like a class to become one.** The scanner turned the plain English
  `shrink` and `resize` into rules; the test is whether the _token_ is a utility name. And **a Tailwind
  palette colour cannot move without changing a computed string**: `text-yellow-400` is
  `var(--color-yellow-400)`, which PR 32 deletes, and the literal is folded by lightningcss.
- **A gallery case for a component that can return `null` is a timeout, not a blank image**:
  `expectCaseShot` waits for the wrapper to be _visible_, and an empty `div` never is. And
  **`TooltipTrigger asChild` overwrites `Button`'s `data-slot`**, so `[data-slot="button"]` misses every
  tooltip-wrapped action — the `sidebar.tsx` trap from PR 11, in another shape.
