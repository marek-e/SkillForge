## Animations

`data-open:animate-in` / `data-closed:animate-out` become ten `stylex.keyframes` (two on the
overlay, one per side and per direction) with `--tw-enter-*` / `--tw-exit-*` substituted by hand.
`slide-in-from-right-10` is **`10%`**, not `2.5rem`: tw-animate-css emits four declarations for the
same variable and the `--percentage-10` branch (`calc(.1 * 100%)`) is the last that matches an
integer argument. The untouched defaults are written out (`scale3d(1, 1, 1)`, `rotate(0)`,
`blur(0)`), because `filter: blur(0)` is not `filter: none`. Durations come from `--tw-duration` /
`--tw-ease`: sheet overlay `100ms`/`ease`, content `200ms`/`cubic-bezier(0.4, 0, 0.2, 1)`, drawer
overlay tw-animate-css's own `.15s`/`ease`. `animation-name` is the one computed value the migration
cannot keep, so the four new frames pin the curve instead. `DrawerContent` has no animation utility
at all — vaul drives it with an inline transform, left alone.

## Observed pre-existing defects (nothing was fixed)

- **The mobile sidebar sheet ignores `--sidebar-width`**: `w-(--sidebar-width)` (18rem) loses to
  `data-[side=left]:w-3/4`, so it is 75% of the viewport — 292.5px at 390.
- **`<SheetHeader className="sr-only">` is not screen-reader-only**: `.p-4` beats `.sr-only`'s
  `padding: 0` on emission order, leaving a 32×32 clipped box, not a 1×1 one.
- **Neither content element sets `overflow`**: a body taller than the viewport runs off the edge.
- **`duration-100` on the sheet overlay applies to `transition-property: all`**, so every property
  transitions over 100ms. **`supports-backdrop-filter:` is a no-op.**
- **The `route * error` captures and the first `animations.spec.ts` cases are timing-dependent** —
  they wait out TanStack's backoff, or run while the server warms. Both passed on a warm re-run,
  and a second full dev run was green end to end (576 passed, 4 skipped).

## Findings for conventions.md

- **A comment may only name the utility the source actually had.** A second shape of the scanner
  trap: a _bare_ utility in a comment for a class the file only used with a variant prefix emits a
  rule that never existed — 16 here. The full original class is accurate _and_ diff-free.
- **Write a shadow colour the way Tailwind writes it.** `#0000001a` and `rgb(0 0 0 / 0.1)` differ:
  Chromium serialises the hex alpha as `0.102` (26/255), and lightningcss does not minify the
  percentage form back to hex, so it survives into the asset.
- **`text-base` is the one paired line-height that can stay a ratio.** `calc(1.5 / 1)` folds to
  exactly `1.5`, so the rounding the length rule avoids cannot happen, and the number keeps the
  ratio inheritable. `input.tsx` and `field.tsx` wrote `1.5rem`; both compute the same here.
- **An unlayered library stylesheet outranks Tailwind _and_ StyleX equally.** vaul styles the drawer
  overlay from its own injected sheet, so its `0.5s` / `cubic-bezier(0.32, 0.72, 0, 1)` beat
  `animate-in` before and the StyleX longhands after: the translation is inert either way.
- **`data-open:` maps to `:is(:where([data-state="open"]), :where([data-open]:not([data-open="false"])))`** — both branches and the (0,1,0) weight, since `:where()` adds none.
- **A caller can overwrite `data-slot`.** `sidebar.tsx` passes `data-slot="sidebar"` after
  `SheetContent` set `data-slot="sheet-content"`: a component that spreads `...props` last has no
  fixed hook, and the mobile sheet matches none of the selectors the other sheet tests use.
