## What the translation had to get right

- **A literal `color-mix()` is folded at build time.** `bg-black/10` with a literal `#000` becomes
  `#0000001a` plus `lab(0% 0 0 / .1)`, which Chrome reports where Tailwind reports `oklab(0 0 0 / 0.1)`.
  Every pixel matched; the dumps caught it. A `var()` in the mix stops the fold.
- **Four keyframes from one variable-driven pair.** `tw-animate-css` ships one `@keyframes enter` and one
  `exit` whose every value is a `var()` set per element by the `fade-*` / `zoom-*` utilities, so one pair
  behaves as four. `stylex.keyframes` hashes frames, so the four resolved forms are written out and the
  eight declarations emit **four** names. `animation-name` cannot be preserved: the dumps leave it out
  and `animations.spec.ts` now pins the exit curve too.
- **The alert dialog's header is a three-way grid.** Three rules write `grid-template-rows`, ordered in
  Tailwind by specificity: the base, the `:has([data-slot=alert-dialog-media])` one, and the one that
  also asks about `data-size` above 40rem; in StyleX the two conditional values nest inside the condition
  they share. `place-items` and `gap` are written as longhands, and the `group-data-` variants keep
  Tailwind's `:is(… *)` match set without the specificity-only `:where()`.

## Built CSS and live verification

Against a plain build of `48f7505` the Tailwind layer loses `.animate-in`, `.animate-out` and the five
`group-data-[size=…]` rules only the alert dialog named, and gains no utility: the six leaks doc comments
caused were reworded away, and every kept class now lives in a named `const`. `.backdrop-filter` (the
scanner reading the `@supports` condition the migration emits verbatim) is in both builds; the gallery
build adds `.w-[900px]`. StyleX: 47 classes added (579 → 626) plus four `@keyframes`.

Dev server on 4320 with `VITE_VISUAL_GALLERY=true`, headless Chromium, `console` / `pageerror` /
`requestfailed` listeners. Create dialog on `/skill-library`, add and delete dialogs on `/projects`: all
open, Escape and outside click close them, `elementFromPoint(12, 12)` is `dialog-overlay`, the scroll lock
is `overflow: hidden` while open and `visible` after every close with `scrollY` unchanged. Focus returns to
the trigger from the gallery panels; the app's three dialogs drop it to `<body>` (pre-existing, below). The
alert dialog (gallery only) ignores an outside click, closes on Escape and returns focus. Two console
entries, both the pre-existing missing-`Description` warning; no `pageerror`, no failed request.
`pnpm --filter @skillforge/electron typecheck` passes.

## Observed pre-existing defects (none fixed)

- **`CommandDialog` renders its header, title and description outside `DialogContent`** and the portal;
  they are `sr-only` but sit in the page whether the palette is open or not. **`CreateSkillDialog` and
  `AddProjectWebDialog` have no `DialogDescription`**, which Radix warns about on every open.
- **A dialog has no maximum height and no scroll container**: `dialog-tall` grows past both edges of a
  scroll-locked viewport, so neither end can be reached.
- **`data-[size=default]:max-w-xs` and `data-[size=sm]:max-w-xs` are the same declaration** (only the `sm:`
  step distinguishes the two sizes), and **`AlertDialogFooter` keeps `flex-direction` and
  `justify-content` in the small size**, where the element is a two-column grid and neither applies.
- **The app's dialogs drop focus to `<body>` when they close**: `CreateSkillDialog`, `AddProjectWebDialog`
  and `DeleteProjectDialog` are controlled through an `open` prop with no `DialogTrigger`, so Radix's
  focus scope has nothing to hand it back to — identical frozen.

## Findings for conventions.md

- **Keep every surviving Tailwind class in a named `const`**: the scanner reads comments as well as code,
  so a comment naming `text-sm` re-emits the utility the migration just removed.
- **`stylex.keyframes` hashes frames**, so a variable-driven Tailwind keyframe splits into one name per
  resolved value set; `animation-name` is then not comparable — leave it out of the dumps and pin both
  curves with frame screenshots.
- **`-mx-4` is `margin-inline` and `-mb-4` `margin-bottom`**: keep Tailwind's own logical-versus-physical
  choice per utility, and give a wrapped child's box to the component's `sx` prop, not a second class list.
- **Tailwind orders competing rules by specificity, StyleX by nesting depth**; and a literal `color-mix()`
  is folded by `lightningcss` into an equivalent but differently spelled colour, so keep a `var()` in it
  when the computed string must match.
