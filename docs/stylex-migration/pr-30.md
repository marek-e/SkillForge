## What became StyleX, and what stays Tailwind

`stylex.create` covers all six elements the route renders itself: the `space-y-4` pending-project
wrapper, the `space-y-6` page wrapper, the `flex items-center gap-3` title row, the
`flex items-center gap-4` heading row, the `flex items-center gap-1` action group and the
`space-y-2` pending-skills wrapper. `space-y-*` migrates for the reason PR 26 and PR 27 gave: every
element it reaches is one this route renders, a `Skeleton`, or a component declaring no
block-direction margin — and the dialogs and the closed `Tooltip` render nothing in place, so
`:last-child` resolves against the same DOM before and after.

by the plain `text-muted-foreground` utility) and the restated `aria-expanded:bg-muted` one. The

## New cases

`routes.spec.ts` already freezes the route in populated / empty / loading / error × light / dark ×
desktop / mobile (plus `project detail reduced motion`), covering both star states (`populated` is
a favourite, `empty` is not), and PR 24 froze the overview card's **long path** and all three
**dialogs** as `projectsx` cases. That leaves two route-local states nothing reaches, in
an appended `routesproject route states` block that `-g routesproject` selects exactly; their 24
originals were captured with `--update-snapshots=missing` on the clean base **before** the route
was touched, then re-run green.

1. **`routesproject skills pending`** — the `space-y-2` skills skeleton stack, which needs the
   project query resolved while `useProjectSkills` is still pending. `loading` mode hangs _every_
   endpoint, so the earlier `isPending` branch wins there; a second `page.route` registered
   **after** `installApiMock` (the most recently added matching handler wins) hangs only
   `/projects/:id/skills`, and freezes the refresh button disabled with its spinning icon.
   `networkidle` is unusable then, so the wait is the heading plus the first `main` skeleton.
2. **`routesproject header action hover`** — the four actions hovered in turn: where a wrong
   `@media (hover: hover)` wrapper, a dropped `ghost` arm or a `group/button` class that stopped
   reaching the star would show. They are located through `h1`, its parent and
   `[data-size="icon-xs"]` — never a class, and not `data-slot`, which a `TooltipTrigger`
   overwrites on the refresh button (PR 24).

## Observed pre-existing defects (nothing was fixed)

- **The header row never wraps**: `H1` is `text-4xl` beside a fixed avatar and a four-button group
  in an `items-center` row with no `min-width`, so a long name would push the actions off the right
  edge. No fixture has one, which is why no case pins it.
- **The favourite star ignores the theme**, as PR 24 recorded for the table, and **only the refresh
  action has a tooltip** — the other three offer no label.

## Findings for conventions.md

- **A route can migrate and add nothing to the built CSS.** Every declaration deduped onto a class
  an earlier row emitted, so the asset kept its content hash: next to the "Tailwind portion
  byte-identical" gate, a **zero**-class diff is the expected result for a late row.
- **For a `Button` override the `sx`-versus-`className` line is drawn by the colour, not the
  component.** Four identical `ghost` `icon-xs` buttons sit side by side; the one whose hover
  colour is a theme token moves, the three taking a Tailwind **palette** colour cannot.
- **A case needing one endpoint pending and the rest resolved registers a second `page.route` after
  `installApiMock`** (the most recently added matching handler wins) but must then drop `settle`,
  because `networkidle` never fires while a request hangs — the only way to reach a route's
  second-level pending branch, since the `loading` data mode is all-or-nothing.
