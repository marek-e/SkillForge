## Carousel

21 utilities, all geometry; none styles a caller-provided child, so the file keeps **no** Tailwind.

| Part                       | Original classes                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| `Carousel`                 | `relative`                                                                               |
| `CarouselContent` viewport | `overflow-hidden` (takes no `className`, so it is a plain `stylex.props` spread)         |
| `CarouselContent` track    | `flex` + `-ml-4` \| `-mt-4 flex-col`                                                     |
| `CarouselItem`             | `min-w-0 shrink-0 grow-0 basis-full` + `pl-4` \| `pt-4`                                  |
| both controls              | `rounded-full absolute touch-manipulation`                                               |
| `CarouselPrevious`         | `top-1/2 -left-12 -translate-y-1/2` \| `-top-12 left-1/2 -translate-x-1/2 rotate-90`     |
| `CarouselNext`             | `top-1/2 -right-12 -translate-y-1/2` \| `-bottom-12 left-1/2 -translate-x-1/2 rotate-90` |
| the two labels             | `sr-only`                                                                                |

1. **The gutter stays physical.** `-ml-4`/`pl-4` compile to `margin-left`/`padding-left`, and Blink
   resolves a physical longhand over the logical property that maps to it whatever the source
   order. The vertical arm is the mirror pair, so the orientations never contest a property and
   each is a style object rather than a condition.
2. **The controls go through `Button`'s `sx`, not `className`.** `Button` is StyleX already; a
   utility would have worked only because a layer beats a selector. Through `sx` the override lands
   in the same layer as what it overrides, and still replaces the whole `border-radius` of the
   `icon-sm` size — including its `in-data-[slot=button-group]:rounded-lg` arm. A caller's `sx` is
   appended after these; a caller's `className` still wins over both.
3. **`-translate-y-1/2` writes both axes.** Tailwind sets `--tw-translate-y` then re-declares
   `translate: var(--tw-translate-x) var(--tw-translate-y)`, so the untouched axis resolves through
   its registered `0`; both are written out (`translate: '0 -50%'`). `rounded-full` stays
   Tailwind's literal `calc(infinity * 1px)`; `min-w-0` is `0rem`, not `0px`.

## Toaster

- **`text-md` is dead and stays.** No `--text-md` exists in Tailwind v4's theme or the project's
  `@theme inline`, so the class never matched a rule — the built CSS has no `text-md` selector. It
  is kept as `TITLE_NO_OP_CLASS` so the rendered `class` attribute does not change for no reason,
  and leaves with the rest of the bridge in **PR 32**.
- **`--toaster-background` now comes from `colors.toasterBackground`.** Sileo puts it on the SVG
  `fill` _presentation attribute_ of the rects it draws the toast from, where `var()` does resolve.
- **Sileo's stylesheet is injected unlayered at import time**, so `[data-sileo-title]` and
  `[data-sileo-description]` outrank every layered rule — a Tailwind utility in `utilities` as much
  as a StyleX class in `priorityN`. Of the four declarations this file makes only the description's
  colour is live; Sileo wins the title's weight and colour and the description's size, at the same
  values. All four are written out anyway — the migration moves the declaration, not the outcome —
  and the `cartoast toast` computed-style snapshots pin which side wins. `text-sm`'s paired
  line-height is written as the length it resolves to (`0.875rem` / `1.25rem`).
- The gallery pins Sileo's three wall-clock timers rather than disabling them (a ten-minute
  `duration`, `autopilot` either immediate or equally far away); `autopilot: false` is ignored when
  there is no duration and the description would never render. Three `toast.*` calls do not stack
  into three elements, so the stack case asserts `toHaveCount(1)`.

## The one case still failing: `cartoast toaster placement` (mobile)

Both themes differ from their originals by 18–38 pixels of at most **6/255**, in a 12×16 box that
is exactly Sileo's badge icon. Everything else in the row is green.

1. **Not the migration.** Swapping `toaster.tsx` back to its `ee0f797` source reproduces the same
   18-pixel difference, three runs of three. The badge is Sileo's markup; this file styles only
   `[data-sileo-title]` and `[data-sileo-description]`.
2. **Not a missing wait — but one was missing anyway.** `[data-sileo-canvas]`, the gooey filter's
   surface, is still moving when the three `waitForStable` calls return: it passes
   `85.5 → 88.9 → 90.15` and lands on `90` about 400ms in, and a capture in between gets a 92px
   canvas. `waitForStable(page, '[data-sileo-canvas]')` is now part of `showToast` and removed one
   of the two failure modes.
3. **What is left is the rasteriser.** With the canvas settled and the subtree byte-identical
   across runs (`742/90` every time, confirmed by instrumenting the real test), eight fresh
   Chromium launches under the config's exact pinning flags still produce **two** images — seven
   the original, one not; the same eight _without_ those flags produce the original every time. The
   unstable pixels are a translucent badge (`oklch(… / 0.2)`) composited over a Gaussian-blurred
   SVG, the case `playwright.config.ts` already warns about in `launchOptions`.

A filtered `--workers=1` rerun reuses one browser across the four tests and lands in the minority
state about half the time, so isolation does not clear it. No tolerance was widened and no original
was refreshed or deleted. **For the orchestrator:** drop the two placement tests and their four
originals (the gallery case stays — its own case shot and the section shot are stable), or move the
assertion off the pixels onto the toast's box. Either removes an original, which is outside a row
agent's remit.

## Observed pre-existing defects

Nothing was fixed.

- **`carousel.tsx` has no caller outside the gallery** — like `ContextMenu` (PR 13).
- **`Carousel`'s `orientation || (opts?.axis === 'y' ? …)` fallback is dead**: `orientation`
  defaults to `'horizontal'`, so `opts.axis` alone never selects the vertical layout.
- **`ArrowLeft`/`ArrowRight` are captured on the root regardless of axis**, so a vertical carousel
  is driven by the horizontal arrow keys and `ArrowUp`/`ArrowDown` do nothing.
- **The `select` handler's cleanup removes only `select`**, leaving `reInit` attached.
- **`row-brief.md` is not Prettier-clean**: `pnpm format` rewrites it. It was restored to its
  committed content rather than reformatted, being outside this row.

## Findings for conventions.md

Not applied here; `conventions.md` is the orchestrator's.

1. **A third-party stylesheet injected at import time is unlayered and beats both sides.** Writing
   the declaration out is still right, but the row needs a computed-style snapshot to prove which
   side wins, because no screenshot can.
2. **A dead class is still part of the rendered `class` attribute**, so it belongs in a named const
   with the reason, not deleted mid-migration.
3. **Prefer a migrated child's `sx` prop over `className` for a component's own overrides** — the
   same outcome by layer order rather than by a layer beating a selector.
4. **A JS-driven animation needs a settle helper per sprung part.** Sileo needs four (toast, pill,
   badge, canvas) and the last is invisible — the filter's surface, not what the filter draws.
5. **`animations: 'disabled'` finishes animations, it does not freeze them.** A settle loop
   comparing consecutive captures taken that way changes the page it measures; a first attempt at
   this row's settle turned an intermittent failure into a constant one.
6. **A blurred SVG under a translucent element is not reproducible at `threshold: 0`.** The
   `launchOptions` flags reduce it but do not remove it; pin such a composite on desktop only, or
   assert geometry instead of pixels.
