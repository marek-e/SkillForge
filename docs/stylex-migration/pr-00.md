## Observed pre-existing defects

Recorded, not fixed. Each of these must still be true after the migration.

1. **`pnpm typecheck` and `pnpm lint` already flag `apps/ui/src/components/app-sidebar/app-sidebar.tsx`**: `SidebarRail` is imported but its usage is commented out (`TS6133` / `eslint(no-unused-vars)`). This is unchanged by this PR; `pnpm typecheck` fails on `main` for the same reason.
2. **`pnpm knip` already fails**: `apps/ui/src/components/app-sidebar/nav-user.tsx` is an unused file. `knip.json` tries to ignore it at the stale path `src/components/nav-user.tsx`.
3. **Nested `<main>` elements**: `SidebarInset` renders a `<main>`, and `Layout` renders a second `<main>` inside it. The inner one is the scroll container. The suite has to select the _last_ `<main>` for scroll handling because of this.
4. **`SidebarMenuSkeleton` randomises its width** with `Math.random()` at mount, so it renders differently on every load, and differently between the dev server and the production build (React's StrictMode double-invokes state initialisers in development only, so the random sequence advances a different number of times). Captured as `quirk-sidebar-menu-skeleton`; the suite pins `Math.random` to a constant so the same original holds for both pipelines.
5. **`ElectronTitlebar` resolves `isMac` at module scope**, so in a browser it always renders the Windows/Linux window controls. Captured as `quirk-electron-titlebar-web`.
6. **Error states are mostly invisible.** `/skill-library` renders "No skills saved yet." when its query _fails_, and `/skill-library/$skillId` renders nothing at all (`if (!skill) return null`). Only `/tools`, `/tools/$name`, `/projects` and `/projects/$projectId` show an `ErrorContainer`. All of these are frozen as-is under the `error` data mode.
7. **`ToolCardCompact` renders `<img src="">` for an unrecognised tool.** `getToolConfig` falls back to `logo: ''`, and React logs _"An empty string was passed to the src attribute"_. No current route can reach this, because the runtime only returns known tool names; the gallery does, as `quirk-tool-card-compact-unknown-empty-logo`. This is the only console error produced by the whole walk of the eight routes and the nine gallery sections.
8. **`components/ui/not-found.tsx` still carries a commented-out earlier implementation** above the live one, and `app-sidebar.tsx` carries a commented-out `<SidebarRail />`.

### Comparator self-test

The comparator was proven to fail on a single pixel:

One pixel of `desktop/routes.spec.ts/home-populated-light.png` was inverted in place (decoded into a Chromium canvas, pixel `(10, 10)` XORed, re-encoded), then:

```bash
pnpm --filter @skillforge/ui exec playwright test --project=desktop -g 'route home populated light'
# -> 1 failed
#    Error: expect(page).toHaveScreenshot(expected) failed
#      1 pixels (ratio 0.01 of all image pixels) are different.
```

The original was then restored from its backup and the same command reported `1 passed`. The comparator rejects a single altered pixel, which is the property the whole gate depends on.

### Determinism

The whole suite was run twice back to back against the originals with zero diffs, which is the gate for committing them. Two sources of jitter had to be removed to get there:

- **Rasterisation.** Chromium re-rasterises dirty tiles across several raster threads with runtime-selected Skia paths, which moved 1–8 pixels per run on rounded corners, on the `dark:invert` tool logos and on composited overlays. `playwright.config.ts` now launches Chromium with `--disable-partial-raster`, `--num-raster-threads=1`, `--disable-skia-runtime-opts`, `--disable-checker-imaging`, `--disable-threaded-animation`, `--force-color-profile=srgb`, `--font-render-hinting=none` and `--disable-lcd-text`. No tolerance was raised and no mask was added.
- **Error-state timing.** TanStack Query retries a failed query three times with a 1 s/2 s/4 s backoff. A five second quiet window occasionally fired between two retries and froze the loading state instead of the error state; the window is now eight seconds, wider than the longest gap, and also requires that at least one request was served.

### Live verification

- `vite` dev server on :4320 with fixtures: all eight routes and all nine gallery sections walked in Chromium with console, `pageerror` and `requestfailed` listeners attached. Exactly one problem was reported across the whole walk: the empty `src` warning from `quirk-tool-card-compact-unknown-empty-logo` (defect 7 above). No failed requests, no uncaught errors.
- Overlays opened and closed by pointer; focus, expanded and active states exercised through `gallery.spec.ts`.
- Electron: the shell is covered in Chromium with a faked `window.electronAPI` for both `darwin` and `win32`, on three routes in both themes, plus an element screenshot of the titlebar. That exercises the `.electron-app` sidebar offset rules, the custom titlebar and the Electron-only project actions.
- The real Electron host is **not** run by default. It was attempted here with `VISUAL_ELECTRON=1 pnpm exec playwright test -g 'electron window light'` against the existing `apps/electron/dist/main.cjs`, and it timed out: `apps/electron/src/main.ts` boots the embedded runtime _before_ it creates the window, and `better-sqlite3` in this workspace is built for the Node ABI, not the Electron one, so `firstWindow()` never resolves. Making it work needs `pnpm --filter @skillforge/electron rebuild-sqlite` and would put real local `data.db` content on screen, which no frozen original can depend on. The test therefore stays gated behind `VISUAL_ELECTRON=1` and skips otherwise; `docs/visual-testing.md` records the exact steps for running it by hand.

## Notes for the next PRs

- Run `pnpm visual` **and** `VISUAL_BUILD=1 pnpm visual` before merging anything that touches the Vite plugin list.
- Add gallery cases for a component _before_ migrating it; `gallery.spec.ts` discovers cases from the DOM, so a new case fails until its original exists, and `visual:update` is the only sanctioned way to create that original.
- Never widen `maxDiffPixels`, never add a mask, never refresh an original.
