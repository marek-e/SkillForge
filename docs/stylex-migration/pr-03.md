## The translation

Every value comes from [`tailwind-values.md`](tailwind-values.md) §1 (`--spacing: 0.25rem`),
§3 (font sizes, weights, tracking, leading), §5 (`border`, `rounded`) and §11 (the `@layer base`
defaults that the components deliberately keep inheriting). Each declaration carries its original
class as a comment.

| Component    | Was                                                                                                                                                                     | Notable mappings                                                                                                                                                               |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `H1`         | `scroll-m-20 text-4xl font-extrabold tracking-tight`                                                                                                                    | `scrollMargin: '5rem'`, `2.25rem` / `2.5rem`, `800`, `-0.025em`                                                                                                                |
| `H2`         | `scroll-m-20 border-b pb-2 text-3xl font-semibold tracking-tight first:mt-0`                                                                                            | `borderBottomStyle/Width` only (colour stays with `@layer base`), `marginTop: { default: null, ':first-child': '0rem' }`                                                       |
| `H3`–`H6`    | `scroll-m-20 text-{2xl,xl,lg,base} font-semibold tracking-tight`                                                                                                        | `1.5/2`, `1.25/1.75`, `1.125/1.75`, `1/1.5` rem                                                                                                                                |
| `P`          | `leading-7 [&:not(:first-child)]:mt-6`                                                                                                                                  | `lineHeight: '1.75rem'`, `marginTop: { default: null, ':not(:first-child)': '1.5rem' }`                                                                                        |
| `Lead`       | `text-xl text-muted-foreground`                                                                                                                                         | `colors.mutedForeground`                                                                                                                                                       |
| `Large`      | `text-lg font-semibold`                                                                                                                                                 | —                                                                                                                                                                              |
| `Small`      | `text-sm font-medium leading-none`                                                                                                                                      | `lineHeight: 1`: `leading-none` sets `--tw-leading: 1`, which `text-sm`'s `var(--tw-leading, …)` also resolves to, so the pair is a plain `1` whichever rule the cascade picks |
| `Muted`      | `text-sm text-muted-foreground`                                                                                                                                         | —                                                                                                                                                                              |
| `Blockquote` | `mt-6 border-l-2 pl-6 italic`                                                                                                                                           | `borderLeftStyle/Width` only, colour from `@layer base`                                                                                                                        |
| `Code`       | base `relative rounded bg-muted px-[0.3rem] py-[0.2rem] font-mono text-sm font-semibold`, `block` variant `block w-full overflow-x-auto rounded-lg border bg-muted p-4` | `rounded` is Tailwind's built-in `0.25rem`, **not** a `--radius` step; `p-4` written as four longhands (see below); the repeated `bg-muted` dropped                            |

Three details are load-bearing:

- **`border-b` / `border-l-2` move only width and style.** Tailwind writes the style through
  `--tw-border-style` (default `solid`) and the colour comes from the `* { border-color: var(--border) }`
  rule in `@layer base`, which StyleX does not contest. Setting `borderColor` in StyleX would have
  been a silent change in dark mode, where `--border` is `oklch(1 0 0 / 10%)`.
- **`p-4` in the `block` code variant is written as four longhands.** StyleX ranks a shorthand
  _below_ a longhand, so a `padding` shorthand in `block` would have lost to the base's
  `paddingLeft`/`paddingTop` — the opposite of what `twMerge` did, which deleted
  `px-[0.3rem] py-[0.2rem]` outright. `borderRadius` needed no such care: it is the same property
  in both objects, so the later one wins.
- **Paired line-heights are written as lengths, not ratios.** This is the one thing that failed
  on the first attempt; see below.

### The line-height precision trap

Writing `lineHeight: 'calc(2.5 / 2.25)'` — Tailwind's own `--text-4xl--line-height` — is wrong.
The unplugin runs its CSS through `lightningcss.transform`, which folds the `calc()` and
serialises the result to **five decimals**: `1.11111`. A longer literal is rounded identically
(`'1.1111111111111112'` also emits `1.11111`). Tailwind never hits this because its ratio lives
inside a custom property that nothing folds, so the browser divides at full precision.

The first migrated run failed on exactly this, in every theme and viewport:

| Element | Tailwind | StyleX with the folded ratio | Box height     |
| ------- | -------- | ---------------------------- | -------------- |
| `H1`    | `40px`   | `39.99996px`                 | `40` → `39.98` |
| `H3`    | `32px`   | `31.9999px`                  | `32` → `31.98` |
| `Muted` | `20px`   | `19.99998px`                 | `20` → `19.98` |
| `Code`  | `20px`   | `19.99998px`                 | `74` → `73.97` |

The fix is to write the length the pair resolves to (`text-4xl` → `fontSize: '2.25rem'`,
`lineHeight: '2.5rem'`), which is exact, is the number Tailwind's ratio was derived from, and
produces a byte-identical `line-height` in the computed-style snapshots. `leading-7` (`1.75rem`)
and `leading-none` (`1`) were already exact and are kept verbatim. Recorded in
[`conventions.md`](conventions.md#paired-line-heights-never-write-the-ratio) for every later row.

The one thing this gives up is that a unitless line-height would pass its _ratio_ down to a
descendant with a different font size. No caller nests differently sized text inside a typography
component today, and every `text-*` utility sets font-size and line-height together, so nothing in
the suite or in the live walk moves.

## Component shape

All 12 follow the pattern in [`conventions.md`](conventions.md#component-pattern-className-bridge-during-coexistence):

```tsx
const variantStyles = { default: null } as const

const H1 = React.forwardRef<HTMLHeadingElement, H1Props>(
  ({ className, style, variant, ...props }, ref) => {
    const sx = stylex.props(styles.base, variantStyles[variant ?? 'default'])
    return (
      <h1
        ref={ref}
        className={cn(sx.className, className)}
        style={sx.style || style ? { ...sx.style, ...style } : undefined}
        {...props}
      />
    )
  }
)
```

- `variant` keeps its `cva` type, including `null`: `VariantProps<typeof h1Variants>` was
  `variant?: 'default' | null | undefined`, and the props interface now spells that out.
  Eleven components have only a `default` variant, which added no classes, so it maps to `null`
  in the lookup — the prop is still read, still accepts `null`, and still never reaches the DOM.
  `Code` keeps `default` and `block`, and still picks its element with
  `variant === 'block' ? 'pre' : 'code'`.
- `className` stays and goes **last** through `cn`, so a caller's Tailwind class still wins — now
  by layer order (`utilities` beats `priorityN`) rather than by `twMerge` deletion.
- `style` is destructured out of `props` and merged, per the convention. In practice these 12
  components have no dynamic styles, so `sx.style` is always `undefined` and no `style` attribute
  is emitted that was not there before. The spread order is unchanged: `className`/`style` are
  written before `{...props}` exactly as `className` was, and neither can appear in `props`
  because both are destructured.

### Removed exports

The 12 `cva` helpers (`h1Variants` … `blockquoteVariants`) are **gone**, from the component files
and from `index.ts`. A repository-wide grep finds no caller outside
`src/components/typography/` — they were re-exported and never imported — so plan rule 6
("check exported variant helpers and every call site before removing them") is satisfied and
keeping them would have left twelve dead Tailwind strings behind. The `*Props` types and the
component exports are unchanged.

Contrast with PR 04, where `buttonVariants` **is** imported elsewhere and therefore stays.

## Why a new gallery section

`gallery.spec.ts` captures one **full-page** screenshot per section on top of the per-case
element shots, so adding a case to `typography` would change `gallery-typography-{light,dark}.png`
— a frozen original that `visual:update` (`--update-snapshots=missing`) cannot rewrite and that
this series never replaces. The 19 new cases therefore live in a sibling section,
`typography-extra`, whose originals are all new. Rule written up in
[`conventions.md`](conventions.md#gallery-cases-are-append-only-per-section).

New computed-style snapshots have no such constraint (a new test name only creates new
originals), so `computed-typography-*.json` reads the **existing** `typography` section without
touching its DOM.

### Cases added

All 19 captured with `visual:update` **before** any component was touched, so the originals show
the Tailwind UI.

| Group                 | Cases                                                                                                                                                                                                                                                                                                                                               |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| flow between siblings | `typography-h2-in-flow` (H2/P/H2/P: `first:mt-0`, the border rule, `:not(:first-child)`), `typography-p-triple`, `typography-p-only-child`, `typography-blockquote-after-p`                                                                                                                                                                         |
| code in flow          | `typography-code-in-paragraph` (inline `code` inside a real line box — padding on an inline box changes the line box), `typography-code-block-overflow` (`overflow-x-auto`)                                                                                                                                                                         |
| wrapping              | `typography-h2-wrapping`, `typography-h3-wrapping`, `typography-lead-narrow`, `typography-blockquote-narrow`, `typography-large-narrow`, `typography-small-narrow`, `typography-muted-narrow`                                                                                                                                                       |
| caller overrides      | `typography-h2-flex-override` (the real `className="flex items-center gap-2"` from `routes/home.tsx`), `typography-h1-size-override`, `typography-p-override`, `typography-code-override`, `typography-blockquote-override` (`border-l-4 pl-4 not-italic`), `typography-code-block-override` (`p-2 rounded-sm` over the variant's `p-4 rounded-lg`) |

The existing `typography` section already covered every component at its default size, stacked
paragraphs, inline vs block code, and two caller overrides; those cases are untouched.

The two computed-style snapshots pin, per element, `font-size`/`line-height`/`letter-spacing`/
`scroll-margin`/`font-style`/margins/padding/border/radius/colour plus the box size — the values
a pixel comparison cannot attribute to a particular declaration. `scroll-m-20` in particular
renders nothing until an anchor jump and would otherwise have been uncovered.

## Built CSS

Production build compared against `855dc51`:

- **Tailwind portion: two rules added, none removed.** `.border-l-4` and `.not-italic`, both used
  by the new `typography-blockquote-override` gallery case. As in PR 01, Tailwind scans
  `visual-gallery/` too, so gallery-only utilities are already in the shipped CSS; these two join
  them.
- Every utility the migrated components used is **still emitted**, because Tailwind's scanner
  reads comments and each declaration names its original class. That keeps the diff small and is
  cleaned up in PR 32.
- One comment did add a rule that nothing renders: `` `mt-0` `` written out in `h2.tsx` made
  Tailwind emit `.mt-0`. The comment was reworded to "the zero step of the spacing scale" and the
  rule went away — the hazard [`conventions.md`](conventions.md) already warns about, now seen in
  practice.
- **StyleX portion: 35 classes added, none removed.** The new `scroll-margin` declaration
  introduces a property-priority bucket that did not exist before, so StyleX's `priority2`…
  layers each shift down by one (`border-color` moved from `priority2` to `priority3`, and so on).
  The relative order of every rule is unchanged, the layer names are all declared up front in
  `index.css`, and the canary and token cases still render identically.
