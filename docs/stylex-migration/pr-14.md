## The finding that mattered: one animation, two independent variant groups

`NavigationMenuContent` composes `enter`/`exit` from two utility sets that can be active at once:
`data-[motion=from-start]:slide-in-from-left-52` and its three siblings, and — inside a
`viewport={false}` menu — `group-data-[viewport=false]/navigation-menu:data-open:zoom-in-95`. In
Tailwind both are `(0,2,0)` and it does not matter which wins, because each only contributes a
different `--tw-enter-*` input to the same `enter` animation. StyleX gives an element one
`animation-name`, so the combinations are enumerated: ten keyframes for the content, two each for
the viewport and the indicator, five for the menubar.

Ordering is settled by structure: `data-[motion=…]` is a **top-level** bare attribute key (5000)
with the `group-data-[viewport=false]` branch **nested** inside it (5040), so the combined variant
outranks both halves while the viewport-less `data-open:` branch alone stays at 2080.
`MenubarContent`'s per-side slide uses the same shape. The `data-[motion^=…]` prefixes are written
as their four exact values: Radix builds the attribute as `` `${enter ? 'from-' : 'to-'}${dir}` ``
with `dir` restricted to `start | end`, and the slide distance is per-value anyway.

## Observations

- **Built CSS.** The Tailwind `@layer utilities` block is byte-for-byte identical to a build of the
  base (1387 rules either side); `theme`, `base`, `properties` unchanged; StyleX stays at
  `priority1 … priority10`. It only got there after a reword: the first build grew `.animate-in`,
  `.animate-out`, `.fade-in`, `.fade-out`, `.origin-center` and `.origin-top` from comment prose.
- **`animation-duration` while closed.** Tailwind sets the animation longhands only inside the
  `data-open:` rule, through the `animation` shorthand; StyleX declares duration and timing function
  unconditionally and switches only the name, so a closed overlay computes `0.1s` rather than `0s`.
  Nothing renders differently — there is no `animation-name` — but a snapshot would see it.
- **0 ms animation frames are load-sensitive.** With a second full suite on the same machine, one
  pass failed `nav-content-open light 0ms` and the rerun failed four _pre-existing_ frames while the
  new ones passed; the clean pass was taken once the machine was free.

## Live check

Headless Chromium with console/`pageerror`/`requestfailed` listeners: pointer and keyboard traversal
of the menubar (click, hover-to-switch, `ArrowRight`/`ArrowLeft` between menus, `ArrowDown` inside
one, submenu on hover, `Escape` returning focus to the trigger), and the navigation menu opened by
hover and by `Enter`, `Tab` into the panel, dismissed by pointer-away and by `Escape`, plus the
`viewport={false}` variant. Computed values match: the composed ring+shadow chains, `28px` inset
padding, `opacity: 0.5` when disabled, 16×16 icons, `muted/50` on an active link with an `8px`
radius inside the panel, `0.3s` in a viewport-less panel, and `transform-origin: 148px 70px` on the
viewport — the default `50% 50%`, confirming `origin-top-center` is inert. Only console output: the
mocked runtime's `ERR_CONNECTION_REFUSED`, which the gallery has either way. Neither component is
mounted by a real route, so the second surface was the `overlays` gallery section.

## Pre-existing defects (preserved, not fixed)

- `focus-visible:outline-1` on `NavigationMenuTrigger` and `NavigationMenuLink` is inert:
  `outline-none` writes `--tw-outline-style: none`, which `outline-1` re-reads for its
  `outline-style`, so a focused element gets one pixel of `none`.
- `MenubarCheckboxItem` has no `data-disabled:opacity-50` while the other items do, so it does not
  dim when disabled.
- `data-inset={inset}` renders `data-inset="false"` for an explicit `inset={false}`, which the bare
  `[data-inset]` that `data-inset:pl-7` compiles to matches too.
- `navigationMenuTriggerStyle` carries `data-popup-open:` variants, base-ui's shape for the open
  state, which no Radix element here ever has.
- `MenubarContent`'s `duration-100` also lands as a `transition-duration` on an element with no
  `transition-property`, so it rides on the initial `all`.

## Findings for `conventions.md`

1. A comment must never name a _composable_ utility without its variant prefix — six rules appeared
   in the built CSS from explanation alone. Naming the full original class stays right.
2. When one animation's inputs come from two independent variant groups, enumerate the
   combinations as keyframes, not the groups.
3. Priority follows nesting: a bare attribute key is 5000 and each level adds 40, so the stronger
   attribute at the top with the weaker inside makes the combination outrank both halves.
4. `stylex.create` needs literal keys — no computed keys, no spreads.
5. The bare `shadow` utility is the deprecated `--shadow` token: the same layers as `shadow-sm`.
