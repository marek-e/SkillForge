## The finding that mattered: `Select.Value` throws `className` away

`radix-ui`'s `Select.Value` destructures `className` and `style` out of its props, drops both and
forces a `style={{ pointerEvents: 'none' }}` of its own. That is _why_ the trigger styled it from
the outside with four `*:data-[slot=select-value]:…` utilities, and moving them onto `SelectValue`
silently produced an unstyled span: `overflow` went back to `visible`, the span's automatic
minimum size stopped being zero, and the long option stopped clipping — 22 screenshots, every one
of them a full page of the section, failed on that one 240px trigger.

They are back on the trigger as StyleX descendant keys (`':is(*)>[data-slot="select-value"]'`,
the mapping `conventions.md` gives for `*:data-[slot=x]:y`); the usual objection to a descendant
key — a caller's utility would outrank it — cannot apply, precisely because the primitive refuses
a `className`. `*:data-[slot=select-value]:line-clamp-1` writes `display: -webkit-box` and
`*:data-[slot=select-value]:flex` writes `display: flex`, both `(0,2,0)`, and the built CSS emits
the second later: `flex` wins today, the clamp has never done anything, and `overflow: hidden` is
what matters. All four are kept.

## Findings for conventions.md

1. **A primitive can refuse a `className`.** Before moving a `*:data-[slot=x]:…` rule from the
   parent onto the child component, check that the primitive forwards `className` — `radix-ui`'s
   `Select.Value` does not. When it does not, the rule stays on the parent, where a StyleX
   descendant key is safe precisely because no caller can contest it either.
2. **Tailwind's scanner reads English prose, not just token-like strings.** Three words in the new
   comments each grew the built CSS by a rule no element uses: `shrink`, `resize`, and a bare
   `pr-0` where the original class was `has-data-[slot=combobox-chip-remove]:pr-0`. "Name the full
   original class" is necessary but not sufficient — a plain verb is a candidate too. Diff the
   built CSS rule set against a base build after every comment pass; nothing else shows it.
3. `stylex.keyframes` + `lightningcss`: `blur(0)` is emitted as `blur()`.
4. "A class name can itself be the contract", from the child's side: an icon keeps its `size-4`
   only because the button around it writes `[&_svg:not([class*='size-'])]:size-3`.
5. `visual:check-originals` is only meaningful after a **single** invocation covering the whole
   suite: `visual/results` and its `used-originals.log` are wiped at the start of each
   `playwright test`. Worth a line in `docs/visual-testing.md`.
