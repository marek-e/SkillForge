## The animation is the row

All three components animate through `tw-animate-css`, and Tailwind has exactly **one** pair of
keyframes for the whole library:

```css
@keyframes enter {
  from {
    opacity: var(--tw-enter-opacity, 1);
    transform: translate3d(…) scale3d(…) rotate(…);
    filter: blur(…);
  }
}
```

Every `fade-in-0` / `zoom-in-95` / `slide-in-from-top-2` class only sets one custom property those
frames read. A `stylex.keyframes` body is fixed, so the parameterisation has to be resolved at
authoring time: **one keyframes block per combination the component can be in.**

| Keyframes         | From the classes                                        | Body                                              |
| ----------------- | ------------------------------------------------------- | ------------------------------------------------- |
| `enterFromTop`    | `data-open:` + `data-[side=bottom]:slide-in-from-top-2` | `opacity: 0`, `translate3d(0, -0.5rem, 0)`, `.95` |
| `enterFromBottom` | `data-[side=top]:slide-in-from-bottom-2`                | `translate3d(0, 0.5rem, 0)`                       |
| `enterFromLeft`   | `data-[side=right]:slide-in-from-left-2`                | `translate3d(-0.5rem, 0, 0)`                      |
| `enterFromRight`  | `data-[side=left]:slide-in-from-right-2`                | `translate3d(0.5rem, 0, 0)`                       |
| `enterCentered`   | the `data-side`-less fallback                           | no translate                                      |
| `exit`            | `data-closed:fade-out-0 data-closed:zoom-out-95`        | `to { opacity: 0, scale .95 }`, no translate      |

`animationName` therefore becomes a two-level condition — state outside, side inside — and the
three files declare identical bodies, so the compiler's content hash collapses them: **six
`@keyframes` rules in the output for three components.** `enterCentered` exists because a nested
StyleX condition must declare a `default` and because Tailwind would animate an unsided content
with no translate; Radix's popper always sets `data-side`, so it is unreachable in practice.

`animation-name` is the one computed value the migration cannot keep, so the snapshots pin the
curve two other ways: `computed-styles.spec.ts` dumps the six animation longhands, and
`animations.spec.ts` captures 0/100/200 ms of the popover's enter, the tooltip's enter and the
popover's exit. Those timings matter because the two durations differ — `duration-100` on the
popover versus the `--animate-in` shorthand's own `0.15s` on the tooltip — so 100 ms is one's last
frame and the other's two-thirds point.

**`duration-100` sets two things**: `--tw-duration`, which the animation shorthand reads, _and_
`transition-duration`. Both are unconditional utilities, so the popover and the hover card each
carry `animationDuration: '100ms'` **and** `transitionDuration: '100ms'`; the tooltip has neither
class and keeps `transition-duration` at its `0s` initial value. The originals show `0.1s` /
`0.15s` / `0s` and confirm it.

## Smaller findings

- **`data-open:` / `data-closed:` compile through `:where()`.** `tailwind-values.md` §9 quotes
  `&:where([data-state="open"]), &:where([data-open]:not([data-open="false"]))` — (0,1,0). The key
  that reproduces it is `':is(:where([data-state="open"]), :where([data-open]:not([data-open="false"])))'`.
  `switch.tsx` and `checkbox.tsx` (PR 06) use the un-`:where`d `':is([data-state="checked"], …)'`,
  which is (0,2,0); harmless there, but the two forms are not the same rule.
- **lightningcss minifies `blur(0)` to `blur()`**, which is valid — the Filter Effects grammar is
  `blur( <length>? )` with a `0` default — and keeps `rotate(0)` as written.
- **`outline-hidden` needs longhands.** Its forced-colors branch is `outline: 2px solid transparent`,
  a shorthand, and a StyleX condition attaches to a property; it is written as four conditional
  longhands instead. The `outline-width: 3px` and `outline-color: oklab(0.708 0 0 / 0.5)` in the
  snapshots come from a global rule, not from these components.
- **`translate-y-[calc(-50%_-_2px)]`** is `translate: 0px calc(-50% - 2px)` — Tailwind writes both
  axes and the untouched one keeps its registered `0` default, exactly as `display-view-switch.tsx`
  found in PR 04.
- `shadow-md ring-1 ring-foreground/10` composes into six `box-shadow` layers (three `0 0 #0000`
  no-ops, the ring at `calc(1px + 0px)`, and `shadow-md`'s own two), which the originals confirm
  verbatim.
- `rounded-lg` is `var(--radius)` = 10px, `rounded-md` is `calc(var(--radius) - 2px)` = 8px,
  `max-w-xs` is `--container-xs` = 20rem, `w-72` 18rem, `w-64` 16rem.

## Observed pre-existing defects

Nothing was fixed. In addition to the lists in the earlier notes:

- **An `instant-open` tooltip does not animate.** Radix's tooltip has three open states and the
  class list covers `data-open:` (which matches `data-state="open"`) and
  `data-[state=delayed-open]:` only. `TooltipProvider` defaults `delayDuration` to `0`, so the
  third is reachable — the live probe walked the four tooltip sides and the fourth came up
  `data-state="instant-open"` with `animation-name: none` while the other three animated.
  Preserved exactly: the migrated file declares the same two conditions.
- **`HoverCardPrimitive.Portal` is given a `data-slot="hover-card-portal"`** that never reaches the
  DOM — `Portal` renders no host element of its own. Left as found.
- **`PopoverTitle` is typed `React.ComponentProps<'h2'>` and renders a `<div>`.** Left as found.
- **The tooltip arrow is `z-50` inside an element that is already `z-50`**, which does nothing.
  Left as found.
- Not a component defect, but worth recording: at 390px the `popover-collision-end` case's 288px
  content is wider than the room left of its trigger, so it overflows the viewport by 66px. The
  same in both trees — the originals for that case were captured on the clean base and match.

## Findings for conventions.md

1. **A `tw-animate-css` `animate-in`/`animate-out` component needs one `stylex.keyframes` per
   combination of enter modifiers**, because Tailwind parameterises a single `enter` keyframes
   block with `--tw-enter-*` custom properties and a StyleX body is fixed. Put the resulting
   `animationName` behind a two-level condition (state outside, `data-side` inside). Identical
   bodies dedupe by content hash across files, so sharing between sibling components is free.
2. **`duration-N` sets `--tw-duration` _and_ `transition-duration`.** A component that composes it
   with `animate-in` must write `animationDuration` **and** `transitionDuration`; one of them is
   easy to miss and only the computed-style snapshot catches it.
3. **`data-open:` / `data-closed:` compile through `:where()`** — the faithful key is
   `':is(:where([data-state="open"]), :where([data-open]:not([data-open="false"])))'`. The
   `switch.tsx` / `checkbox.tsx` form omits the inner `:where()` and is one specificity class higher
   than Tailwind's rule.
4. **`outline-hidden` is two rules, not one.** Its `@media (forced-colors: active)` branch uses the
   `outline` shorthand, which a StyleX condition cannot carry; write the four longhands.
5. **The paired-`text-*` exception has a third shape**: not a descendant the component renders, but
   a whole _other_ component a caller drops inside it. `calendar.tsx`'s `text-[0.8rem]` cells
   inherit their line height straight from `PopoverContent`.
6. **lightningcss rewrites `blur(0)` to `blur()`** in a keyframes body. Valid, and worth knowing
   before reading a built-CSS diff.
7. **Give a new gallery section and all of its tests one distinctive token in their names.** It
   makes `-g <token>` select exactly the new tests, which is what the "capture the originals on the
   clean base first" rule needs in a worktree where nothing may be checked out.
